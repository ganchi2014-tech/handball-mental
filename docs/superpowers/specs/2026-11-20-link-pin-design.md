# LABとつなぐときのPIN — 2026-11-20

オーナー指示（2026-11-20）：

1. つなぎ方を、つながっていない人に画面で知らせる
2. PINはメンタルアプリの画面で見られるようにする
3. LABでつなぐとき、名前を押したらPINを入れさせて、同じなら許可する

## 前からあった穴

LAB（handball-system）の「チームと繋ぐ」で名簿の名前を押すと、その名前の人のメンタルアプリと
つながる（`/labLinks/{mentalUid}`）。先に押した端末が勝つ作りで、本人かどうかは確かめていなかった。
ほかの人の名前を押せば、その人の「行動宣言」の要約（`/declShared`）が読め、本人はあとからつなげなくなる。

## 作り

- **PINは今までのPIN**（登録のとき決めた4桁）。新しい番号は作らない。
- PINの元の数字はどこにも残していない（端末に崩した形だけがある）。見せるときは 0000〜9999 を試して
  割り出す（`recoverPin`）。割り出せないとき（古い形で数字が重なった・形が無い）は、その場で決め直す。
- 照合用の形 `linkPinHash(mentalUid, pin)` ＝ SHA-256(`handball-link|{mentalUid}|{pin}`) の16進64文字。
  **LAB の `app/src/lib/linkPin.js` と同じ作り方**。両方のテストに同じ答えを置いてある。
- メンタルアプリは、照合用の形を `/linkPins/{自uid}` に置く（読めるのは本人だけ。顧問も読めない）。
  起動のたびに置き直す（割り出しは最初の1回だけ。結果の形を端末に控える。PINそのものは控えない）。
- LAB は名前を押されたら4桁を聞き、
  1. `/linkTries/{mentalUid}/{0..9}` の空いている席に `{labUid, pinHash}` を書く（1回書いたら書き直せない）
  2. `/labLinks/{mentalUid}` に `{labUid, rosterId, try: 席の番号}` を書く
  決まりは「その席が自分の端末のもので、形が `/linkPins/{mentalUid}` と同じ」ときだけ 2 を通す。
  LAB は相手の照合用の形を読めない。比べるのは決まりだけ。
- **回数の壁**：席は1人につき10個。うまると、その人にはもう誰も試せない。
  席を空にできるのは本人（「PINを表示」を押したとき）と顧問。
  端末ごとに数えないのは、匿名の端末番号はいくらでも作り直せるため。
- 先につないだ端末が勝つ決まり・つなぎを消せる人・顧問の名簿番号の付け替えは、今までどおり。

## 守れる範囲

- まちがい・いたずらで他人の名前を押しても、PINが無ければつながらない。
- 道具で総当たりしても、10回で止まる（本人が「PINを表示」を押すたびに、また10回ぶん空く）。
- 守れないもの：本人のメンタルアプリを開いた状態の端末を渡された人（PINが画面で見られる）。

## 画面

- マイ統計に「LABとつなぐ」のカード（選手だけ）：つながっているか／つなぐ手順／PIN（押したときだけ表示）。

## 2つのアプリを行き来する（同日のオーナー指示「相互に飛べるように」）

- メンタル → LAB：行き先は `LAB_URL`（1か所）。ホームのタイル、マイ統計、「LABとつなぐ」、行動宣言の「⚡プレーの宣言」から開く。
- LAB → メンタル：LAB の `MENTAL_APP_URL`。ホーム、「チームと繋ぐ」の手順とPINの欄、メンタルの宣言のカード、宣言の下から開く。
- 行き先の末尾に目印を付ける（`#from=mental` / `#from=lab`。通信には乗らない）。
- **iPhoneでホーム画面に追加して使っている場合の注意**：ホーム画面のアプリとブラウザは、保存場所が別。
  リンクで開いた先はブラウザ側になるので、相手のアプリが「初めての状態」で開くことがある。
  - メンタル側：LABから来て登録の画面が出たら、「ここで登録し直さないで」の知らせを出す（`FromLabNotice`）。
    登録し直すと、名簿とのつながり（`rosterToUid`）がブラウザ側へ移ってしまうため。
  - LAB側：メンタルから来て記録が何も無いときは、「チームと繋ぐはいつものLABで」の知らせを出す。
    その場所でつなぐと、いつものLABがつなげなくなるため（先につないだ端末が勝つ）。
- **つなぎを外す**：ちがう場所をつないでしまったとき、メンタルアプリの「LABとつなぐ」から本人が外せる
  （`/labLinks/{自uid}` を消す。前からある決まりで本人に許されている）。外したあと、PINでつなぎ直す。

## 出す順番

1. メンタルアプリ（この変更）を出す。決まりがまだ無い間、`/linkPins` への書き込みは断られるだけ
   （一番上の決まりが読み書きとも不可なので、何も置かれない）。
2. LAB を出す。LAB は自分の `/linkPins/{自uid}` が読めるかで「決まりが入ったか」を見分ける。
   入っていない間は今までどおり（PINを聞かない）。
3. **データベースの決まりを入れる**（オーナーの作業）：`firebase deploy --only database`、または
   Firebase コンソールの Realtime Database →「ルール」に `database.rules.json` の中身を貼って公開。
   入れた時からPINが要るようになる。もうつながっている人は、そのまま。

1〜3 の順でなくても壊れないが、3 を先に入れると、1 が出るまで新しくつなげる人がいなくなる。
